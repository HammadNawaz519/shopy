3. SYSTEM ARCHITECTURE & ENGINEERING DESIGN PRINCIPLES
================================================================================

1. SUPABASE POSTGRESQL IS THE UNQUESTIONED SOURCE OF TRUTH:
   Permanent business entities (users, orders, products, inventory counts, reviews,
   settings, media assets, and user carts) reside strictly in PostgreSQL. The system
   enforces ACID properties: if an external service or cache fails, the database
   remains uncorrupted.

2. ZERO-THROW FAIL-SAFE REDIS DEGRADATION:
   If Upstash Redis is unreachable, misconfigured, or network-throttled, all data 
   retrieval gracefully falls back to Supabase PostgreSQL without throwing unhandled 
   500 errors or interrupting checkout flows.

3. SERVER-AUTHORITATIVE DATA FLOW:
   Client requests never dictate prices, totals, or stock statuses. The frontend 
   submits only product IDs and requested quantities; the server executes authoritative
   lookups, verifies active discounts, recalculates shipping and tax, and checks stock.

4. CONCURRENCY & RACE-CONDITION DEFENSE:
   - Order placement acquires a distributed lock: `lock:order:[idempotency/user]`.
   - Inventory decrements execute atomically:
     `UPDATE products SET stock_count = stock_count - qty, in_stock = (stock_count - qty > 0) WHERE id = $id AND stock_count >= qty`
   - Database table constraints enforce non-negative inventory: `CHECK (stock_count >= 0)`.
   - Admin status updates acquire row-level locks using `SELECT * FROM orders WHERE id = $1 FOR UPDATE`.

5. REQUEST IDEMPOTENCY:
   The checkout endpoint accepts an `x-idempotency-key` header. The idempotency key 
   is recorded in Redis with a 24-hour TTL upon order creation. Repeated submissions
   with the same key return the previously generated order instantly without 
   double-charging or double-decrementing stock.

6. SINGLE-FLIGHT CACHE STAMPEDE PROTECTION (MUTEX PATTERN):
   When a high-traffic cache entry expires, only ONE serverless invocation queries
   PostgreSQL to re-populate the cache. Concurrent requests await the leader's 
   computation briefly and read the freshly populated cache value.

7. ZERO-CLS VISUAL HYDRATION & BFCACHE OPTIMIZATION:
   All public catalog and product pages feature bespoke Next.js shimmer loading skeletons
   (`loading.tsx`) that match final DOM geometry precisely, preventing layout shifts.
   The browser Back-Forward Cache (BFCache) is restored, and legacy/rogue mobile service
   workers are automatically pruned via `ClientCacheRevalidator.tsx`.

8. CROSS-TAB STATE SYNCHRONIZATION:
   The admin panel leverages HTML5 `BroadcastChannel` (`shopy_admin_orders_channel`)
   to synchronize real-time order arrival counters and seen statuses across multiple
   open browser tabs without redundant polling.

4.12. DISTRIBUTED CACHING, CONCURRENCY CONTROL & MUTEX LOCKS
--------------------------------------------------------------------------------
- Upstash Redis Layer (`lib/redis.ts`):
  - Systematic versioned keys (`shopy:v4:products:*`, `shopy:v4:categories:all`, `shopy:v4:settings`).
  - Granular TTL Strategy:
    - Products Catalog: 10 minutes (600s).
    - Product Details: 15 minutes (900s).
    - Categories: 30 minutes (1800s).
    - Store Settings: 1 hour (3600s).
    - Homepage Config: 30 minutes (1800s).
    - Order Idempotency: 24 hours (86400s).
- Atomic Distributed Locking:
  - Implements `acquireDistributedLock(key, ttl)` via Redis `SET key value NX EX`.
  - Generates cryptographically unique lock tokens (`timestamp_randomBytes`).
  - Verified Ownership Release: Lock is released ONLY if the current value matches
    the caller's token, preventing premature unlock by delayed executions.
- Single-Flight Cache Stampede Protection:
  - `fetchWithStampedeProtection(cacheKey, fetcher, ttl)` ensures only one serverless 
    instance queries the database during cache expiration.
- Efficient Batch Invalidation:
  - `redisDelPattern(pattern)` uses Redis `SCAN` in non-blocking batches of 50 keys,
    preventing Redis main thread stalls during catalog updates.

5. DATABASE ARCHITECTURE & RELATIONAL SCHEMA SPECIFICATION
================================================================================

The platform uses a relational PostgreSQL schema designed for high-throughput 
e-commerce, strict referential integrity, and sub-millisecond query execution:

1. `categories`:
   - Columns: `id` (PK), `slug` (UNIQUE), `name`, `tagline`, `image`, `description`,
     `aspect_ratio` ('tall' | 'square'), `featured` (BOOLEAN), `created_at`, `updated_at`.
2. `products`:
   - Columns: `id` (PK), `name`, `slug` (UNIQUE), `category_id` (FK categories),
     `category_slug`, `category_label`, `price`, `original_price`, `description`,
     `tag` ('NEW' | 'SALE' | 'LIMITED' | 'ARCHIVE'), `images` (TEXT[]),
     `colors` (JSONB), `sizes` (TEXT[]), `composition` (TEXT[]), `care_instructions` (TEXT[]),
     `details` (TEXT[]), `featured` (BOOLEAN), `in_stock` (BOOLEAN),
     `stock_count` (INTEGER CHECK stock_count >= 0), `created_at`, `updated_at`.
3. `product_images` (Relational Gallery with Source-of-Truth Ordering):
   - Columns: `id` (PK), `product_id` (FK products ON DELETE CASCADE),
     `image_url`, `storage_path`, `sort_order` (INTEGER NOT NULL DEFAULT 0),
     `created_at`, `updated_at`.
4. `users`:
   - Columns: `id` (PK), `name`, `email` (UNIQUE), `password_hash`,
     `role` ('user' | 'admin'), `reset_token`, `reset_token_expiry`, `created_at`, `updated_at`.
5. `orders`:
   - Columns: `id` (PK), `order_number` (UNIQUE), `user_id` (FK users ON DELETE SET NULL),
     `subtotal`, `discount`, `shipping`, `total`, `status`, `payment_status`,
     `payment_method` ('cod' | 'bank_transfer' | 'online' | 'card'),
     `payment_details` (JSONB), `shipping_address` (JSONB), `notes`,
     `created_at`, `updated_at`.
6. `order_items` (Historical Price Snapshot):
   - Columns: `id` (PK), `order_id` (FK orders ON DELETE CASCADE),
     `product_id` (FK products ON DELETE SET NULL), `name`, `price`,
     `quantity` (INTEGER CHECK quantity > 0), `size`, `color`, `image`, `created_at`.
7. `discounts`:
   - Columns: `id` (PK), `code` (UNIQUE), `type` ('percentage' | 'fixed'), `value`,
     `min_order`, `usage_limit`, `usage_count`, `active`, `expires_at`, `created_at`.
8. `reviews`:
   - Columns: `id` (PK), `product_id` (FK products ON DELETE CASCADE),
     `user_id` (FK users ON DELETE SET NULL), `order_id` (FK orders ON DELETE SET NULL),
     `product_name`, `customer_name`, `customer_email`, `rating` (CHECK 1..5),
     `comment`, `status` ('pending' | 'approved' | 'rejected'), `created_at`.
9. `store_settings`:
   - Columns: `id` (PK), `store_name`, `support_email`, `currency`, `currency_symbol`,
     `free_shipping_threshold`, `flat_shipping_rate`, `tax_percentage`,
     `order_notifications`, `inventory_alert_threshold`, `cod_enabled`, `bank_transfer_enabled`,
     `bank_account_holder`, `bank_account_title`, `bank_name`, `bank_account_number`, `bank_iban`,
     `bank_raast_id`, `bank_payment_contact`, `bank_payment_instructions`, `updated_at`.
10. `media_assets` (PostgreSQL Binary Image Storage):
    - Columns: `id` (TEXT PK), `filename` (TEXT), `mime_type` (TEXT), `data` (BYTEA),
      `size_bytes` (BIGINT), `created_at` (TIMESTAMPTZ DEFAULT NOW()).
11. `user_carts` (Cross-Device Cart Persistence):
    - Columns: `user_id` (VARCHAR PK REFERENCES users(id) ON DELETE CASCADE),
      `items` (JSONB NOT NULL DEFAULT '[]'::jsonb), `updated_at` (TIMESTAMPTZ DEFAULT NOW()).
12. `newsletter_subscribers`:
    - Columns: `email` (PK), `subscribed_at`.
13. `inquiries`:
    - Columns: `id` (SERIAL PK), `name`, `email`, `subject`, `message`, `created_at`.
14. `navigation_items`:
    - Columns: `id` (PK), `name`, `href`, `order_index`, `is_active`, `category_slug`,
      `created_at`, `updated_at`.
15. `homepage_config`:
    - Columns: `id` (PK), `hero_title`, `hero_subtitle`, `hero_image`, `hero_cta_text`,
      `hero_cta_link`, `featured_title`, `featured_subtitle`, `editorial_tag`,
      `editorial_title`, `editorial_quote`, `editorial_image_1`, `editorial_image_2`,
      `newsletter_title`, `newsletter_subtitle`, `updated_at`.

Specialized Performance Indexes:
- `idx_products_cat_created`: Composite index on `(category_slug, created_at DESC)`.
- `idx_products_feat_created`: Composite index on `(featured, created_at DESC)`.
- `idx_products_stock`: Composite index on `(in_stock, stock_count)`.
- `idx_product_images_product_id`: Btree index on `(product_id)`.
- `idx_product_images_sort_order`: Composite index on `(product_id, sort_order)`.
- `idx_orders_shipping_email`: Functional btree index on `LOWER(shipping_address->>'email')`.
- `idx_orders_user_created`: Composite index on `(user_id, created_at DESC)`.
- `idx_orders_status_created`: Composite index on `(status, created_at DESC)`.
- `idx_reviews_prod_status_created`: Composite index on `(product_id, status, created_at DESC)`.
- `idx_reviews_user_prod`: Composite index on `(user_id, product_id)`.
- `idx_navigation_active_order`: Composite index on `(is_active, order_index ASC)`.
