================================================================================
SHOPY LOGIN WORKFLOW
================================================================================

The Android app is a Capacitor shell that loads the deployed SHOPY site at
https://buyatshopy.vercel.app. The WebView cookie jar on that origin is the
session authority.

1. SESSION MODEL
----------------
The server creates a signed seven-day JWT in the httpOnly cookie
"shopy_session_id". It also sets the JS-readable marker cookie
"shopy_client_auth=1". Email/password and Google sign-in both use this same
session mechanism.

2. EMAIL/PASSWORD LOGIN
-----------------------
The login page posts credentials to /api/auth/login. The route validates the
request, verifies the password, creates the normal SHOPY session, and returns
the authenticated user. The AuthContext stores the user locally and requests
carry the session cookie automatically.

3. CLASSIC WEB GOOGLE LOGIN
---------------------------
On desktop and ordinary web browsers, GoogleButton redirects to
/api/auth/google. The existing OAuth state cookie protects the Google callback
at /api/auth/callback/google. The callback exchanges the authorization code,
upserts the user, creates the normal SHOPY session, and redirects to the
requested destination.

4. ANDROID NATIVE GOOGLE LOGIN
------------------------------
The Android path does not use browser OAuth, Chrome, Custom Tabs, deep links,
handoffs, polling, or a callback page.

Flow:

  SHOPY WebView
      |
      | Capacitor NativeGoogleAuth.signIn()
      v
  Android Credential Manager
      |
      | real Google account picker / Google ID token
      v
  NativeGoogleAuth Capacitor plugin
      |
      | ID token returned to JavaScript
      v
  POST /api/auth/google/native
      |
      | server verifies token audience, email, and email_verified
      v
  existing SHOPY user lookup/upsert + createSession(user)
      |
      | shopy_session_id and shopy_client_auth cookies
      v
  WebView navigates to the requested destination

The native Android implementation is:

  android/app/src/main/java/com/shopy/fashion/auth/NativeGoogleAuthPlugin.java

It uses Jetpack Credential Manager with Google Identity Services
GetGoogleIdOption. The plugin returns only the Google ID token through the
Capacitor bridge. No Google client secret is shipped to Android.

The /api/auth/google/config endpoint returns BOTH the web client id and
GOOGLE_ANDROID_CLIENT_ID (exposed as androidClientId). The in-app button
passes the WEB client id to Credential Manager as serverClientId (Google
requires the Web application client, not the Android client). The server
verifies the returned ID token against those configured client ids.

One-time Google Cloud setup for the native flow:
  1) Credentials (project: shopy-new): OAuth client type ANDROID,
     package com.shopy.fashion, SHA-1 of the APK signing key
     (make-shopy-apk.bat prints it in step [5/5]).
  2) Credentials: OAuth client type WEB — this is GOOGLE_CLIENT_ID and
     the value passed into Credential Manager.
  3) Optional: GOOGLE_ANDROID_CLIENT_ID = the Android client id (extra
     token audience only; not sent to the native plugin).

5. SERVER FILES
---------------
app/api/auth/google/route.ts
  Classic web OAuth start route only.

app/api/auth/callback/google/route.ts
  Classic web OAuth callback only.

app/api/auth/google/native/route.ts
  Receives the native ID token, calls completeNativeGoogleSignIn(), sets the
  standard SHOPY session cookies, and returns the authenticated user.

lib/security/googleAuth.ts
  Contains classic OAuth helpers and verifyGoogleIdToken().

lib/security/googleAuthFlow.ts
  Shares user lookup, creation, role handling, and session creation between
  classic web OAuth and native ID-token sign-in.

6. ANDROID FILES
----------------
android/app/build.gradle
  Includes androidx.credentials and Google Identity Services dependencies.

android/app/src/main/java/com/shopy/fashion/MainActivity.java
  Registers NativeGoogleAuthPlugin.

android/app/src/main/AndroidManifest.xml
  Contains no Google OAuth browser or custom-scheme deep-link intent filter.

7. LOGOUT
---------
Logout calls /api/auth/logout, clears the SHOPY session cookies, clears cached
user state, and returns the app to the guest state.

8. ENVIRONMENT
--------------
Required server values include the Google OAuth client ID, OAuth client secret
for the classic web flow, and the session/JWT secret. GOOGLE_CLIENT_SECRET is
server-only and must never be exposed to the Android app or WebView.

The Android native flow requires Google Play Services and a correctly
configured Google web OAuth client ID. The signing certificate and package
configuration must also match the Google Cloud project used by the app.
